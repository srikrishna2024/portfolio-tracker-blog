How to Report a Bug

A well-written bug report gets the issue fixed in the next release. A vague one takes three back-and-forth emails to clarify. This page explains exactly what to include and how to send it.

The easiest way — use the built-in tool

The software has a dedicated bug reporting page at Admin → Report a Bug. It automatically collects:

  • Your app version
  • Your operating system and Python version
  • The last 50 lines of the app log (the most useful diagnostic data)

Fill in the form, click Generate, and it produces a complete report you can download as a .txt file and email directly.

Send your report to: Use the email address on the Contact page
Subject line: Bug Report v[your version]: [one-line description]

What to include

1

The generated report (required)

Use Admin → Report a Bug to generate it. It captures version, OS, and log automatically. This is the single most useful thing you can send — without the version number and log, most crashes are impossible to reproduce.

2

Screenshot (strongly recommended)

A screenshot of the error message, blank page, or incorrect number is worth several paragraphs of description. It shows exactly what you see.

Windows: press Win + Shift + S to select an area, then paste into your email. Or press PrtSc for the full screen.

Mac: press Cmd + Shift + 4 to select an area. The screenshot saves to your Desktop automatically.

3

Log file (for crashes)

If the app crashed or showed a Python traceback, attach the log file. You will find it at:

Windows: C:\pages_app\logs\app.log
Mac: ~/pages_app/logs/app.log

The generated report already includes the last 50 lines, but the full file is useful for crashes that happen on startup before the app fully loads.

4

Steps to reproduce (required for non-crash bugs)

Write down exactly what you did before the problem appeared — which page you were on, what you clicked, what you entered. The more specific the better:

Good: "1. Opened Goal Planning → Goal Dashboard. 2. Clicked 'Details — Child Education'. 3. Page went blank."
Not useful: "Goal Dashboard isn't working."

Severity — what to expect

SeverityDefinitionResponse timeFix timeline
🔴 Critical Core feature broken, app crashes on load, data appears incorrect in a way that affects decisions Same day Hotfix release as soon as possible
🟡 Non-critical Something looks wrong or behaves unexpectedly, but you can still use the app Within 48 hours Next scheduled release

When in doubt, report as non-critical — it is easy to upgrade. A critical report that turns out to be non-critical is not a problem.

What we do with bug reports

Every report is logged in an internal tracker with the version it was reported in, severity, and how many users reported the same issue. When a bug is fixed, the fix version is recorded so buyers who reported it can verify the fix in their next update.

If multiple buyers report the same issue, that issue moves to the front of the queue regardless of severity classification. You help everyone by reporting — even if the fix takes a release or two, it is in the queue.

What we cannot help with

  • PostgreSQL or Python installation issues — these are separate products with their own support channels. See the PostgreSQL docs and Python docs.
  • OS permissions and firewall configuration — these are machine-specific and outside the software's scope.
  • Investment advice — the software is a tracking and analysis tool, not a financial advisor. The analysis it produces is for information only.

Ready to report?

Open the software and go to Admin → Report a Bug. The tool generates everything you need in one click.
