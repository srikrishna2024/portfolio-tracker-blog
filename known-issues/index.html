launcher/windows/Start App.bat 👥 1 reporter

⚠️ Open v7.2.0

Restore fund data fails on PostgreSQL 18 — incompatible flags error

1_Admin_Tools/new_backup.py 👥 1 reporter

What happens: Restoring a backup using "Restore to this machine" fails with an error mentioning --clean --create --single-transaction. PostgreSQL 18 does not allow --single-transaction when combined with --create because CREATE DATABASE cannot run inside a transaction block.

✅ Workaround — use the correct restore type for fund data

When loading the pre-supplied fund data files (fund_master_data.dump and nav_history.dump), use this restore type instead:

  1. Go to Admin Tools → Backup → Restore tab
  2. Upload fund_master_data.dump
  3. Select "Load fund prices from a backup (safe, does not touch your personal data)"
  4. Click Restore — wait for it to complete
  5. Repeat steps 2–4 for nav_history.dump

This option is safe — your personal data and transactions are never affected.

Fix scheduled for next release.

What happens: On fresh install .venv doesn't exist yet so _find_python() falls back to sys.executable (system Python). pip install then fails with WinError 5 Access denied on corporate machines where system Python is locked.

shared/db.py / requirements.txt 👥 1 reporter

What happens: psycopg (pure Python) needs libpq.dll from PostgreSQL installation. On machines where PostgreSQL bin is not on PATH, psycopg fails with 'no pq wrapper available'. Affects corporate machines with non-standard PATH.

Fixed in v7.1.3. Update the app to get this fix — go to Admin → Upgrade.

Double-nested folder after extraction — app path has pages_app_v7_1_2_windows inside pages_app_v7_1_2_windows

build_dist.py / zip extraction 👥 1 reporter

What happens: When zip was extracted, the zip had no top-level folder prefix so Windows created the outer folder from the zip name. Files ended up at pages_app_v7_1_2_windows/pages_app_v7_1_2_windows/. All paths were wrong causing run_migrations.py and all other scripts to fail.

Fixed in v7.1.3. Update the app to get this fix — go to Admin → Upgrade.

pg_dump/pg_restore port passed as int to subprocess — TypeError on Windows with PostgreSQL on PATH

1_Admin_Tools/run_migrations.py 👥 1 reporter

What happens: subprocess.run() requires all args to be strings. params['port'] is an int. Works on machines where pg_dump is not found (skipped), fails on machines where PostgreSQL bin is on PATH (PostgreSQL 18).

Fixed in v7.1.3. Update the app to get this fix — go to Admin → Upgrade.

✅ Fixed Fixed in v7.1.2

Setup Wizard fails at Database setup: ImportError connect_to_db_super from shared.db

Setup Wizard → Database setup step (step 3) 👥 1 reporter

What happens: Setup Wizard fails at Database setup with: Tables could not be created: ImportError connect_to_db_super from shared.db. Root cause: Windows internally shortens folder names containing dots+numbers (e.g. pages_app_v7.1.1_windows → PAGES_~1.1_W). This breaks Python loading of compiled .pyd modules. Affects all Windows versions when app is extracted to a path with dots in the folder name.

Fixed in v7.1.2. Update the app to get this fix — go to Admin → Upgrade.

✅ Fixed Fixed in v7.1.3

Backup & Restore cannot find pg_restore.exe — WinError 2 on restore

1_Admin_Tools/new_backup.py 👥 1 reporter

What happens: detect_postgresql_bin_path() only scanned hardcoded C:\Program Files\PostgreSQL. On machines with custom install paths or PostgreSQL 18, the path detection failed and pg_restore.exe was not found.

Fixed in v7.1.3. Update the app to get this fix — go to Admin → Upgrade.

✅ Fixed Fixed in v7.1.3

Start App.bat timeout 30 seconds too short — shows error even when app is running

launcher/windows/Start App.bat 👥 1 reporter

What happens: On first launch packages are loading which takes longer than 30s. Bat file gives up and shows error even though Uvicorn started successfully. User sees error but app is actually accessible at localhost:8501.

✅ Fixed Fixed in v7.1.3

launcher shows App: Not running even when app is accessible — IPv4/IPv6 mismatch

launcher/windows/launch.pyw 👥 1 reporter

What happens: On Windows with IPv6 enabled, localhost resolves to ::1 but port probe checked only 127.0.0.1. Streamlit bound to ::1 so probe failed. Launcher showed Not running but app was accessible.

Fixed in v7.1.3. Update the app to get this fix — go to Admin → Upgrade.

How to report a new issue

If your issue is not listed here:

  1. Open the software and go to Admin → Report a Bug
  2. Fill in the form — it automatically collects your app version, OS, and error log
  3. Download the generated report and email it with any screenshots to the email on contact page

Critical bugs are responded to the same day. Non-critical bugs are fixed in the next scheduled release.
