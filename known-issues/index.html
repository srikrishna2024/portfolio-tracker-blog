Backup & Restore fails with "The system cannot find the file specified" — pg_restore.exe not detected

1_Admin_Tools/new_backup.py → detect_postgresql_bin_path 👥 1 reporter

What happens: Restore fails immediately with [WinError 2] The system cannot find the file specified and the version shows "Unknown". This means the app cannot find pg_restore.exe — the PostgreSQL utility needed to load backup files. This happens when PostgreSQL is installed to a non-standard path or its bin folder is not on the system PATH.

Note: This is separate from the database connection — the app can connect to PostgreSQL fine, but pg_restore.exe is a separate executable that must be located on disk.

✅ Workaround — set the path manually in Settings
  1. Open File Explorer and search for pg_restore.exe on your C: drive (or wherever PostgreSQL is installed)
  2. Note the folder — e.g. C:\Program Files\PostgreSQL\18\bin
  3. Go to Admin Tools → Backup & Restore → Settings tab
  4. Paste the folder path into the "PostgreSQL bin folder" field and click Apply
  5. You should see "pg_restore.exe found ✅" — go back to the Restore tab and try again

Fix shipped in hotfix — replace 1_Admin_Tools/new_backup.py with the latest version (available on request). Ships in v7.2.1.

⚠️ Open v7.2.0

Restore shows "failed" error even when fund data loads successfully — PostgreSQL 18 exits non-zero on warnings

1_Admin_Tools/new_backup.py → do_restore 👥 2 reporters

What happens: After clicking Restore with "Load fund prices from a backup", the UI shows a red Restore failed error. This is caused by PostgreSQL 18 returning exit code 1 even when the restore completes successfully — it treats informational notices and harmless warnings as errors. The fund data may have actually loaded correctly despite the error message.

✅ Workaround — verify using row counts and Data Pipeline

Step 1 — Check row counts on the Restore page:
After the error, look at the row count metrics shown above the Restore button. If Fund master and NAV history show numbers greater than zero, the restore worked. Click 🔄 Refresh row counts to update the display.

Step 2 — Verify in Data Pipeline:
Go to NAV Data Manager → Data Pipeline. If fund names appear in the fund selector dropdowns, the master data loaded correctly. Run Daily Refresh — if it completes without "no funds found" errors, the NAV history is also in place.

If row counts are zero after refreshing, the restore genuinely failed — reply to your support email with the full error text shown in the restore log.

Fix shipped — replace 1_Admin_Tools/new_backup.py with the latest version (available on request). Ships in v7.2.1.

⚠️ Open v7.2.0

CAMS PDF parser picks up noise as scheme names — "Demat)", merger notes, "(Non Demat)" appear in import

shared/debt_statement_parsers.py → _parse_cams_pdf 👥 1 reporter

What happens: Some CAMS statements include tags like (Non Demat), fund merger notes like Treasury Plan - PF Option, ST Gilt Fund merged), or fragment text like Demat) in the scheme listing. The parser picks these up as scheme names, which fail to match any AMFI code — resulting in missing NAV data and understated portfolio values.

✅ Workaround — use the ISIN-based parser instead

The ISIN-based parser resolves scheme names directly from AMFI using fund codes — it completely bypasses name matching and is unaffected by these tags.

  1. Go to Data Import → Equity Import and upload your CAMS PDF
  2. Open the "📥 Parse & Preview CSV (ISIN-based)" expander at the top of the page
  3. Click Parse & Resolve (ISIN) and review the resolved scheme names and codes
  4. If the data looks correct, scroll to the bottom and use Reset Equity Portfolio Data (type RESET to confirm) to clear the previous bad import
  5. Re-import using the ISIN-resolved data

Fix scheduled for next release.

⚠️ Open v7.2.0

Restore fund data fails on PostgreSQL 18 — incompatible flags error

1_Admin_Tools/new_backup.py 👥 1 reporter

What happens: Restoring a backup using "Restore to this machine" fails with an error mentioning --clean --create --single-transaction. PostgreSQL 18 does not allow --single-transaction when combined with --create because CREATE DATABASE cannot run inside a transaction block.

✅ Workaround — use the correct restore type for fund data

When loading the pre-supplied fund data files (fund_master_data.dump and nav_history.dump), use this restore type instead:

  1. Go to Admin Tools → Backup → Restore tab
  2. Upload fund_master_data.dump
  3. Select "Load fund prices from a backup (safe, does not touch your personal data)"
  4. Click Restore — wait for it to complete
  5. Repeat steps 2–4 for nav_history.dump

This option is safe — your personal data and transactions are never affected.

Fix scheduled for next release.

Common mistakes — not bugs, but frequently reported

These are not software bugs — they are setup steps that are easy to get wrong. If something isn't working, check this list first.

📋 Common mistake

Wrong restore type selected when loading fund data — using "Restore to this machine" instead of "Load fund prices"

What happens: User selects "Restore to this machine (replaces current data)" when loading fund_master_data.dump or nav_history.dump. This either wipes existing personal data or fails with an error.

✅ Correct steps

For loading the pre-supplied fund data files, always use:
"Load fund prices from a backup (safe, does not touch your personal data)"
This adds the fund data to your existing database without touching your transactions, goals, or portfolio history.

📋 Common mistake

setup.pyw double-click does nothing — window flashes and disappears

What happens: Double-clicking setup.pyw opens a window that immediately disappears, or nothing happens at all. This occurs when the .pyw file association is not registered correctly — common with some Python 3.14 installations.

✅ Workaround

Use Run Setup.bat instead — it's in the same launcher\windows\ folder and explicitly calls Python regardless of file associations. Double-click it and the setup window will open normally.

📋 Common mistake

App folder name contains dots or version numbers — causes ImportError in Setup Wizard

What happens: Extracting the zip to a folder like C:\pages_app_v7.2.0_windows\ causes Windows to internally shorten the path (e.g. to PAGES_~1.0_W). This breaks Python's ability to load compiled modules and causes the Setup Wizard to fail with an ImportError.

✅ Fix

Rename the app folder to a simple name without dots — e.g. C:\pages_app. Then re-run setup.

📋 Common mistake

"Add Python to PATH" not ticked during Python installation — Run Setup.bat or python commands not recognised

What happens: During Python installation, the checkbox "Add Python to PATH" was left unticked. Windows cannot find Python when you run Run Setup.bat or any other launcher script, showing "Python not found" or "'python' is not recognised as an internal or external command".

✅ Fix

The easiest fix is to reinstall Python — run the Python installer again, and this time tick "Add Python to PATH" on the first screen before clicking Install. Then run Run Setup.bat again.

Alternatively, Run Setup.bat (v7.2.0+) searches the Windows registry and common install folders automatically, so it may find Python even without PATH being set.

📋 Common mistake

Goal Dashboard shows no data after importing portfolio

What happens: Portfolio imports fine and transactions are visible, but the Goal Dashboard shows zeros or empty charts.

✅ Fix — two steps needed after import
  1. Go to Goal Planning → Create a Goal and create at least one financial goal
  2. Go to Goal Planning → Goal Fund Manager and assign your funds to goals

The Goal Dashboard only shows data after funds are mapped to goals. This is the most commonly skipped step.

How to report a new issue

If your issue is not listed here:

  1. Open the software and go to Admin → Report a Bug
  2. Fill in the form — it automatically collects your app version, OS, and error log
  3. Download the generated report and email it with any screenshots to the email on contact page

Critical bugs are responded to the same day. Non-critical bugs are fixed in the next scheduled release.
